# Operational Timeline and Causal Assessment API Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use `superpowers:test-driven-development` for every task and `superpowers:verification-before-completion` before claiming this plan complete.

**Goal:** Serve one read-only, provenance-preserving timeline that joins the active Forzy archive with persisted live telemetry, exposes stable pages/overview/context, and attaches only causally valid assessments without implying continuity, failure, cause, RUL, or sensor placement.

**Architecture:** A timeline service sits beside the existing v2 snapshot service. Its repository adapters read archive and live tables without mutating them; pure modules own total ordering, cursor binding, gap classification, peak-preserving reduction, event-candidate projection, and the single live decision-facts projection shared by timeline context and snapshot. Historical assessments are generated by a new row-level walk-forward exporter and stored against original archive points. Live context continues to use the pinned final model only for points after `trainedUntil`. FastAPI routes delegate to this service and never call the Forzy upstream; the browser consumes backend-owned facts and never rebuilds freshness, collection expectation, trust, candidates, or causal state.

**Tech Stack:** Python 3.12, FastAPI, Pydantic 2, pandas/numpy/scikit-learn pipeline already in the repository, SQLite, PostgreSQL/psycopg 3, pytest 8, existing JSON Schema/AJV/JavaScript contracts from the foundation plan.

**Planning lineage:** `globalBaseCommit=4d1cc82fce1b147a3e50315fafdcd37d90dc9a7e`.

**Execution starting point:** `phaseStartCommit` is the exact `phaseAEvidenceCommit` from A's integrated handoff, containing E1 plus A's reviewed code and evidence-only ledger commit. The handoff separately supplies `phaseAVerifiedCodeCommit`, its PASS verdict, and the evidence-only path set. B requires clean `HEAD == phaseStartCommit`, verifies ancestry and the ledger's stored A code SHA, and never branches or rebases directly from `globalBaseCommit`.

### Frozen query and causal rules

- `GET /api/v2/assets/{assetId}/timeline`, `/timeline/samples`, and `/timeline/context` are read-only. They do not write, refresh, acquire a claim, or call upstream.
- Only `forzy-motor-01` is public.
- Range semantics are `[from,to)`. Both endpoints reject naive timestamps, empty/reversed ranges, unknown sensors/metrics, and out-of-range limits with 422.
- Total order is `(eventAt ASC, samplePairId ASC, sensorId ASC, pointId ASC)`.
- Page default is 200 and maximum is 500. The overview resolves exactly one metric (default `vibrationVelocityRms`). `maxPoints` defaults to 1,200 and accepts 40 through 4,000; it is one global ceiling per sensor/source across all of that combination's segment series, never a new allowance per segment.
- A cursor is opaque transport state, not an authorization token. It contains version, active batch ID, canonical query fingerprint, and the last total-order key; a checksum detects corruption. The server revalidates filters, active batch, and boundary existence. A changed query or superseded batch returns 409.
- Archive and live points are never deduplicated across sources, even if times/values overlap.
- `context?pointId=` selects exactly that original point. `context?at=&segmentId=` selects the greatest original key with `eventAt <= at` inside that segment, or an explicitly recorded open gap immediately adjacent to that segment. The adjacent-gap branch returns a validated empty historical-gap context; unrelated gaps/times are rejected. Exactly one selector form is accepted.
- Missing S1/S2 remains null. There is no zero-fill, interpolation, nearest-neighbor search across a gap, or carry-forward from another segment.
- Archive gap threshold is strictly greater than 15 seconds. Live gaps use the collection policy explicitly linked to the refresh cycle; old live rows without a policy are not retrospectively classified as missed collection.
- Point reduction is `time_bucket_envelope_v1`: for each sensor/source, coordinate one deterministic first/min/max/last selection over all of its points in the effective range, deduplicate point IDs, restore total order, enforce no more than `maxPoints`, and only then partition selected originals back into gap-safe segment series.
- No historical row is evaluated by the final live artifact. Historical output comes only from a walk-forward fold whose training ends before the row's actual trailing window begins.
- Rows without a causal fold or without valid trailing features produce `assessment=null`, not a zero-score normal result.
- Historical `watch`/`alert` rows are review candidates. Ranking is status, persistence, data trust, newest event, candidate ID; raw scores never compare different sensors, folds, sources, or model versions.
- `componentTag` remains null. Timeline data can identify S1/S2 but cannot locate either sensor on motor, pump, coupling, or base.
- The overview returns requested/effective/available ranges, aggregation totals, and the active archive's ordered operating cycles; the browser never reconstructs these facts from reduced points.
- The context returns closed `TimelineDecisionFactsV1`, provenance, and capability facts. Freshness, collection expectation, trust, causal assessment availability, pair completeness, and previous-cycle comparability are computed by the backend from persisted policy/source/time evidence, never from frontend clocks or numeric constants.
- Any `timeline_live_point` is retrospective even when it is the newest live reading: `collectionState=historical_context`, `collectionExpectation=not_applicable`, and `dataFreshness=historical`. A causally supported live assessment normally preserves `conditionSource=live_assessment` with `conditionTemporalScope=historical`; the frozen degraded/insufficient-normal suppression still wins and produces `none/none/null`. Without an assessment the insufficiency/unknown branch remains `none/none/null`. It is never byte-equal to `snapshot_now`, and no frontend adapter may rewrite either variant.
- `CollectionPolicyV1`, `TimelineEventCandidateV1`, overview ranges/aggregation/cycles, and `TimelineDecisionFactsV1` are consumed unchanged from the Foundation schemas/models. B may not duplicate enums, loosen fields, or substitute runtime schedule defaults. The pinned initial policy hash is `sha256:89bde17193c7a34c80d48828f4e61fc5802caa92169d83f8a9fd8e4c282b1bce`.
- All timeline and snapshot cross-references remain JSON Schema draft-07. AJV registers schemas by absolute `$id` before compilation; Python draft-07, Pydantic, AJV, and handwritten JS must agree on every shared fixture. B cannot introduce `$defs`, dynamic anchors, unevaluated properties, or an unresolved relative `$ref`.
- Every public timeline timestamp is the Foundation canonical UTC millisecond form. Source/live provenance may retain finer input precision, but no API range, point, candidate, context or decision fact emits it; projection to the public instant is explicit and identity-tested, and consumers never normalize silently.
- Every successful live snapshot contains required `snapshot.decisionFacts` with the exact closed `TimelineDecisionFactsV1` shape, including nested `schemaVersion="1.0"`. Timeline live context calls the same pure projector with the same original evidence. The frontend may flatten these fields after validation but may not recompute any dimension.
- Event candidates always anchor an original point and use the exact Foundation fields. Historical and live candidate projectors share one validator/identity function; neither downsampled points nor display maxima may create a candidate.
- `OperationalDecisionViewV1` remains a presentation-layer derivative. This backend supplies its complete evidence/time/quality inputs but does not return `summaryCode`, copy, checklists, triage state, ruleset hashes, escalation, or field instructions.
